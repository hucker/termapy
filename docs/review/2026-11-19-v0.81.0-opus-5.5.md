**Scope**, asked for by Chuck after about 60 merges in two weeks, with MCP, `/board` and
`/dev` set aside as preliminary: what a person does in every session. Getting in (every
entry point), making and choosing a config, the session versus the file (setting buttons,
the unsaved-settings question, setters, `/cfg`), and choosing a port.

## Verdict

**Each new piece works on its own; the trouble is where they meet, and "two ways to do
one job" is real.** Making a config has six ways that write to three places with two
different `auto_connect` defaults while the docs and the registry say they make the same
files; keeping a setting has three ways in the TUI and none in the CLI; changing one has
three that differ only in whether they ask. Three High findings, all reproduced: one Save
after picking another port re-points a quick config at a different device, the New Config
dialog writes a config that does not reconnect, and a config's own on-connect setter makes
every session look unsaved, so Exit always asks.

Most fixes are consolidation (one rule, one command, one way to leave), not new features.

## Ways to do one job

| Job | The ways | How they differ | Call |
|---|---|---|---|
| Start with no arguments | TUI, `--cli`, `--vt100` | 0 configs: the TUI writes a demo config and shows Quick Setup, the CLI holds defaults, vt100 exits. 2+ configs: the TUI shows a picker, the CLI prints "No config found", vt100 exits "no config found" | **Merge**: one answer to `find_config`'s three states in every frontend |
| Make a config | New Config dialog, its Advanced, editor Save As, `/cfg.new`, `--new`, quick open (`termapy PORT`), `--demo` | `--new` starts `./termapy_cfg`; the dialog, Save As and `/cfg.new` write where `cfg_dir()` points (the user folder outside a project); quick open always the user folder. The dialog writes `auto_connect: false`, the others `true`. Only quick open turns on the EOL/Echo/Color buttons | **Merge** the four named creators onto one rule (`new_config_from_args`: `auto_connect`, buttons); keep quick open (a session) and `--new` (a project) as the two documented ways |
| Pick a port | Title-bar picker, New Config list, `/port.connect X`, `/port.list` click, quick open, `/cfg port X` | The picker switches and reconnects; `/port.connect X` while connected stays on the old port and reports success | **Merge**: `/port.connect X` switches (or fails); the picker dispatches it |
| Change a setting now | Setters (`/term.echo on`), setting buttons, `/cfg key val`, `/cfg.auto key val` | All session-only; only `/cfg` asks Yes/No in the TUI, `/cfg.auto` exists to skip that | **Remove** the confirm and `/cfg.auto`; the `*` and the leave question already guard |
| Keep a setting | Editor Save, the unsaved question's Save, settings on a quick open | The CLI has none; the docs also say `/cfg.auto` keeps one (it does not) and that only the editor persists | **Add** `/cfg.save` as the one way, in every frontend; the dialog's Save dispatches it |
| Switch config | Picker Load, `/cfg.load`, the New Config dialog's Connect, restarting | The TUI asks about unsaved settings; the CLI drops them silently | **Merge**: one rule for every frontend |
| Leave | Exit, Ctrl+Q, palette, `/exit`, `/cli`, `/vt100`, `--kill`, CLI `/exit` | The first four ask in the TUI; the mode switches and `--kill` do not; the CLI never does | **Merge**: one leave path that asks |

## Recommended order

1. **H1**: a quick config's port is its name. Leave `serial.port` out of a quick config's
   session changes, or have the reopen set it, so `termapy COM7` always opens COM7.
2. **H2, M9**: one rule for every named creator (`new_config_from_args`: `auto_connect`,
   the buttons a config starts with), one destination rule documented, and the "same
   files" sentences and registry row made true.
3. **H3**: measure changes from the session as its config's own on-connect commands
   leave it, not from the file.
4. **M3, M6, M5**: one leave path that asks (mode switches and `--kill` included), and
   `/cfg.save` as the one way to keep a setting in every frontend; then drop `/cfg`'s
   confirm and `/cfg.auto`.
5. **M4**: name a quick config from the port's path (`port_path`), so the short and full
   spellings and a plugged or unplugged port reach one config.
6. **M1, M2**: one answer to "no arguments" in every frontend; decide whether quick
   configs count for auto-load.
7. **M7, M8, M11, M12, M10** and the lows, each small.

## Replaying the walkthrough

From an empty folder with `TERMAPY_CFG_DIR` pointed at another empty folder:
`termapy --alive`, `--ports`, `--ports COM7`, `timeout 8 termapy --watch`;
`termapy --cli COM7 9600 -e "hello loopback"`, then `termapy --cli COM7 -e /term.eol`
(the settings came back); `termapy --cli COM5 -e id` and `-e temp` (Pico),
`termapy --cli COM8 -e id` (ESP32-S3); `termapy --new my_device COM7 9600`, then
`termapy my_device --cli -e /port.baud_rate`; in the TUI: click EOL, Exit (the
question), Save, reopen; pick COM8 in the title bar, Save and Exit, then
`termapy --cli COM7 -e /port.info` (H1). Hold COM7 in another process for M8.

## What worked well

`--ports` and `--alive` are fast and readable; quick open reports Created / Using /
Updated with the full path and its settings persist; lenient spellings (`com7`,
`\\.\COM7`) reach the same config; typos get good did-you-mean lists; `-e` one-shots
wait for the reply; the unsaved question does the right thing in each of its three
answers; the `*` mark reads clearly; `--new` refuses a non-standard rate with the
`custom=true` hint and asks before overwriting.

## Not covered

MCP, `/board`, `/dev`, `/mem`, protocol and CRC, file transfer and `--web`, by scope.
Skimmed only: `port-vars`, `vt100-log`, `picker-port-display`, `tx-chunk`,
`port-state-color`, `running-details`. Not observable in isolation: the real split
between the user folder and `./termapy_cfg` on disk (read from code instead), the first
TUI launch in a real terminal, column dropping on a narrow terminal, the button colors.
macOS not run; Linux only through WSL, with no serial hardware.
