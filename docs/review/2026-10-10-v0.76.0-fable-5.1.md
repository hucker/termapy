**Scope note:** this is the first pass over the protocol and capture
subsystem on its own. It was picked because the previous day's merge
(`fix/register-spec-word`) turned up two defects here in passing — a
capture that raised on the reader path, and `.pro` specs parsed during a
Textual render with no guard — and where there are two, there are usually
more. The subsystem has two jobs: describe bytes (`Name:U1-2`, CRC
columns, bit fields) and move them (capture a stream to CSV, run a `.pro`
script against a device). The stated standard is unchanged: a serial tool
that silently writes the wrong numbers is a tool that gets thrown away.

**Verdict:** the *describing* half is sound where it is exercised —
`parse_hex` is strict, `parse_pattern`/`match_response` are byte-exact,
CRC wire order agrees between the send side and the spec, and the bit
model (`B`/`b`, multi-byte ranges, `extract`/`inject`, the word binding)
is one consistent LSB0-over-combined-value rule. The *moving* half is
not fit for use at its advertised size. **Every structured capture longer
than one 4 KB flush is misframed** (C1, reproduced: 634 of 2000 rows
wrong, and `records=N` never auto-stops), and in the TUI **`echo=on`
makes the serial reader block on the main thread once per line** (C2,
exact-path read), which is the one callback shape the threading rules
forbid and the shape `stop_reader`'s own error text names. Neither needs
hardware to see; both have been present since `CaptureEngine` was
extracted (2026-03-24). Raw `/cap.bin` and `/cap.text` are fine. `/proto.run`
is correct for short scripts against a live device but cannot be
interrupted (P4). Fix C1 (one line) and C2 (route the echo through
`_rx_enqueue`) before anyone, human or agent, captures a stream with a
`fmt=`.

---

## Root cause: three decoupled halves

**The flush was built for bytes and later got records.** `_flush_bin`
writes the whole-record prefix of its buffer and then clears *all* of it
(`capture.py:355-385`): the partial record at the tail is discarded, the
byte count undercounts by the same amount, and the next buffer starts
mid-record. C1, C5, C6 and C7 all live in those forty lines. The test
suite crosses the 4096-byte flush only in raw mode or with a 4-byte record
that divides 4096 exactly, so the straddle was never exercised.

**The spec parser accepts shape, the consumers assume range.** `_parse_byte_refs`
has no lower bound (so `U0` is Python index −1 — the last byte), the value
formatters zero-pad data shorter than the spec, and a CRC `(range)` is
parsed and carried but nothing computes over it. P1, P2, P3 and P5 are
each a parse that succeeded where it should have refused, met by a
consumer that trusted it.

**The command reports its own success, not the engine's.** `start_capture`
returns False and the handler returns `CmdResult.ok` anyway and skips the
`cmd=` (C4); `_cap_stop` leaves the port claimed inside a script and the
CLI/MCP never release it (C3); `/proto.run` reads a `json_file` key it
never writes (D1). In each the user-visible outcome is decided before the
thing it describes has happened.

## Invariants checked and holding

Verified by the orchestrator unless marked (finder):

- `parse_hex` is strict — odd nibble counts and `ABC` raise (finder; consistent with the `test_protocol` suite).
- `parse_pattern` / `match_response` are byte-exact with length enforced: a valid-CRC frame against `01 03 02 ** **` passes (verified in the P2 probe).
- CRC wire-order defaults agree between `_parse_send_algo` and the format spec (`refout`-derived, explicit `_le`/`_be` wins); `crc16-xmodem_le` round-trips (finder).
- One bit model: `B`/`b` ascending/descending rendering, multi-byte ranges, `extract`/`inject`, and the LE/BE word binding in `resolve_word_columns` agree on LSB0 over the combined value; `inject` refuses an over-wide value (verified yesterday in `test_protocol_word_fields.py`, re-read here).
- Raw-mode `target_bytes` trimming is exact; the `_target_done` latch keeps "capture N bytes" exact despite the asynchronous stop (finder; `test_capture.py:537-600` covers it for raw mode).
- `feed_text` and `_flush_bin` catch `(OSError, ValueError)` on writes and surface them as an abort; `_record_write_error`'s identity check ignores a failure against a handle `stop()` already closed; `stop()` is idempotent; `start()` refuses while active and leaks no handle on an open failure (finder).
- The reader-to-UI path for lines / clear / capdone / error / disconnect is non-blocking via `_rx_enqueue` (finder; C2 is the one callback that bypasses it).
- `/cap.poll` honors `script_stop_event` and never clears it; `/cap.wire` is hard-capped at 5 s (finder).
- Setting-command discipline: `/proto.hex` bare-queries, `/proto.hex 2` → `Invalid value: 2 (use on/off/toggle)`; every boolean in both files goes through `parse_bool`/`parse_bool_setting` with an erroring unknown-token path (finder, reproduced).
- Error-message style: every `fail(` string in both files is keyword-led or sentence case; the two `Usage:` literals are the documented holdouts (finder).
- The format-type table is single-sourced: the generated blocks in `protocol-testing.md` and README agree with the parser, and the hand quick-reference in `data-capture.md:110-122` agrees with them (finder).
- The `.pro` TOML grammar matches its doc for every *documented* key; defaults (1000 ms / 50 ms) agree; the three shipped demo scripts use only documented keys and pass (finder, run).
- `crc.py` is a thin registry over crcglot with no local CRC math (verified by read).

## Suggested remediation order

1. **C1** — `del self._buf[:usable]`; add a test that feeds 4096+1 bytes with a 3-byte record and asserts alignment and the `target_bytes` stop.
2. **C2** — route `on_echo` through `_rx_enqueue`; the test is a `feed_bytes` from a non-main thread with `echo=True` under `run_test()`.
3. **C4** — `if not started: return CmdResult.fail(...)` at all four sites; C3 — release the claim on stop regardless of `in_script` unless a script-level claim exists (it does not), and give CLI/MCP the release path.
4. **P2** — either compute the CRC over the data range in `diff_columns` (and document `(range)`) or delete the range syntax and the docstring claim; honor the mask per byte for multi-byte columns.
5. **P1** — lower-bound check in `_parse_byte_refs`; **P3** — `?`/`missing` for any column whose indices exceed the data.
6. **D1** — either make `/proto.run` honor `json_file` and `wants_data`, or move the key's documentation to a new `--proto` section.
7. **P4** — check `script_stop_event` between steps and replace the `time.sleep` with an interruptible wait; add a Stop control to the debug screen.
8. The minors (C5–C8, P5–P7, D2–D8) as a cleanup branch.
