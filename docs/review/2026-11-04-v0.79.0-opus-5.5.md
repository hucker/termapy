## Verdict

**Two sentences at the center of the MCP page are false on main today:** "nothing an agent runs can write" `plugin/` or `viz/`, and "A write never replaces a file" (`help/mcp-server.md:220-221`, repeated at README:139 and in CLAUDE.md). Four routes break them, and none needs a flag.

**None of this has shipped.** Both sentences arrived in `d5aab7f0` on 2026-11-03 and are not in v0.79.0, so this can be fixed before they reach a release.

The gate itself is sound. `/os`, rename and delete, and `/cfg.load` all held when probed, and today's merges closed A5 and the delete half of A4. The defects are in writers that do not pass through the guards, which is what `mcp-no-code-writes` being an assumption with no test allows.

**Why tests missed P1:** `test_mcp_boundary.py` checks the writers it knows about, so a writer nobody listed passes. The two outside `builtins/commands/` (`write_results`, `run_legacy`) would also escape a guard that only walks plugin modules. A real guarantee needs one write primitive (`ctx.fs`) and an `ast` walk that refuses any other write in reachable code, which is a larger change than the fixes above.

## Decisions for you

1. **P2: make it true, or reword?** I recommend making it true, by refusing `/port <other>`, `/port.connect <other>` and `/cfg port` when `config_fixed` is set. A server named `termapy-left` that can move to the right board defeats the reason to name it. Rewording to "the config stays; an agent can still repoint its port" is one sentence.
2. **`spy://` under `TERMAPY_MCP_NET_EGRESS`:** I recommend refusing it regardless, as in P1c.
3. **Still open from 2026-11-03:** whether to remove the three `TERMAPY_MCP_*` flags.
