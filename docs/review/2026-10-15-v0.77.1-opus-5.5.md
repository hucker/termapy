**Scope note:** earlier passes were scoped by mechanism (threading 08-19,
serial path 10-14, protocol and capture 10-10, `/mem` 09-18). This one takes
the command surface as a whole and asks Chuck's question: do the commands
work consistently and conveniently in production? Production here means
three readers: a person at the TUI, a `.run` script that reads `success`
and `value`, and an MCP agent that reads the JSON envelope. The prompt was
the pattern found twice this week, the same thing done three ways (`/raw`
on 10-14, five hex readers on 10-13). This pass went looking for the rest
of that pattern.

**Verdict:** where one table, builder or reader owns a concern, termapy is
consistent, and the guards keep it that way: one dispatch exit, the folder
builders, the `/term.*` settings, the bool and hex readers, the error
vocabulary. Where no single owner exists, the three-ways pattern is
everywhere. There are three sources of it:

- **Frontends that register their own copy of a command.** `/delay` has
  four implementations, `/expect` two, and the session-log path six
  resolvers. `/help.open`, `/cfg.load`, `/log.delete` and the `/edit`
  family are rebuilt by the TUI.
- **Concepts with no reader.** Durations, endian, filters and the
  verbs `clear` and `show` each mean different things in different commands.
- **Handlers that judge their own outcome.** About a dozen commands print
  a red line and return success.

Fitness: **sound for a person watching the screen**, because the red lines
are there to read. **Not yet trustworthy for unattended scripts or MCP
agents**, which read `success` and `value`. A failed `/port.baud_rate`, a
failing `/proto.run` suite and a missing `/show` file all report success. A
silent delay in the TUI does not wait, and `/proto.crc.detect` answers a
confident "no match" for spaced hex that `/proto.crc.find` matches. Eight
High findings, all reproduced or read at the exact path; none is a killer.
Most are small to fix once each concern has an owner. The fix pattern is
the 10-13 hex pass: one owner per concern, plus a guard.

## Strengths

What is done one way everywhere, and what keeps it that way:

1. **One exit, one envelope.** Every dispatch return goes through
   `_finish` (`repl.py:1893-1927`), so the JSON envelope, the red error
   line and the table rendering happen in one place for every command and
   frontend. The CLI `--json` envelope and the MCP response are the same
   dialect. Verified: read.
2. **Families are built, not written.** `folder_ops.build_folder_subcommands`
   gives cap, ss, run, proto and plugin the same list / explore / rename /
   show / dump / clear set (`folder_ops.py:426-487`); `folder_ops.file_table`
   is the one file-list shape; `edit.edit_command` builds both `/edit.<f>`
   and `/<f>.edit`. Adding a data folder adds its verbs. Verified: read.
3. **The `/term.*` settings follow the setting rule.** Nine booleans take
   `{on|off|toggle}` through `_bool_setting` / `_cfg_toggle`
   (`term.py:39-60`); eol, eol.rx, output and json take `cycle`; bad input
   fails with the standard `Invalid value: X (use ...)`. This family is the
   model the `/port.*` setters should copy (S1). Verified: read; Reported:
   the counts.
4. **The error vocabulary mostly holds.** `"No config loaded."` appears
   verbatim at 31 sites with no variant. Wrong arity goes through
   `raise UsageError()` at 52 sites, and a hand-written `Usage:` survives
   only in the documented holdouts. Reported: grep counts.
5. **The guards are green and do their job.** 38 architecture tests pass
   at `2bae794`. Inside their scan scope, no handler parses bool tokens or
   hex by hand, no handler reaches `_write`, handlers are named one way,
   and markup is escaped. Several findings below are holes at the edge of
   a guard's scope, not failures inside it. Verified: run.
6. **Shared keywords mean one thing.** `cmd=` is the trailing
   command-to-run keyword in ping, repeat, cap.text, bin, poll and wire, the
   CRC find and reverse commands, and profile.load. Every duration
   declared through `params` uses `type="duration"`. Reported.
7. **Legacy renames are registered once by the engine**
   (`LEGACY_FORWARDERS`, `repl.py:433-456`), not per frontend. D9 is the
   exception. Reported.

## Decisions that are Chuck's

Each changes behavior a script can see, so the call is his:

1. **A filter that matches nothing**: failure or empty success? One answer
   for every list and search (S3, V4).
2. **`/proto.crc.detect` frames**: keep one frame per token, as crcglot's
   verb manifest defines it, or read spaced hex as one packet like the rest
   of `/proto.crc.*` (V1). If the answer changes the manifest, the fix lives
   in crcglot, not in an app-side override.
3. **Endian spelling**: `be|le` or `big|little` (crcglot uses
   `big|little|both`), accepted everywhere and printed in the same form it
   is read (V2).
4. **Duration units**: do the `*_ms` config keys and `/port.break` take
   `parse_duration` text (`50ms`), and what does a bare number mean (V3)?
5. **The verbs**: rename `/cap.clear` and `/ss.clear` to `.delete` (and
   decide `/mem.clear`), or rewrite the recorded rule; decide whether `/show`
   means print or open (V5).
6. **`/expect`**: one default timeout (5 s as documented, or 250 ms), and
   whether a timeout aborts a running script on every path (D1).
7. **`/cfg` in a TUI script**: bypass the confirm dialog, or wait for its
   answer before returning (D7).
8. **Legacy aliases**: drop them, or keep them (K1).

## Suggested remediation order

Mechanism first: one owner per concern, plus a guard, as in the 10-13 hex
pass.

- **A — a failure is a failure (S1-S5, X1).** `port_control` returns a
  problem the handler maps to `CmdResult.fail`, as `/term.*` already does.
  `/proto.run` fails when any test fails, with `data` still attached.
  Handlers stop printing their own errors, so `fail(msg="")` goes away. The
  gate says `Not connected.` for `serial_connected`. XMODEM receive refuses
  an existing name or receives into a temporary file. Guard: an `ast` check
  that a handler never returns `ok` on a path that wrote a red line, and
  never returns `fail(msg="")`.
- **B — one implementation per command (D1-D10).** `/delay` and `/expect`

- **C — one reader per concept (V1-V9).** Durations through `parse_duration`

- **D — answer shapes (A1-A4).** A runtime check in the test suite that

- **E — text and cruft (E1, K1).** After A-D, since several slips disappear
