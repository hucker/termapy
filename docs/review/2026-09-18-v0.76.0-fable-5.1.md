**Scope note:** the recent work turned `/mem.*` from "your variables" into "your
variables plus the silicon's registers" (device files), and then added the
gates that make the second half defensible: refuse a sweep over registers,
refuse reads of write-only registers, log every register read. This pass
attacks exactly those gates, because the stated standard is that a tool
which creates one undetectable device bug is a tool that gets thrown away.

**Verdict:** the design is right and cheap — address containment from the
loaded device file, the vendor's `access` field, the session log — and the
read side holds under attack. Two mechanism gaps remain, both on the write
side of the same bargain and both reproduced here. **The plain `/mem.write`
reads its target before writing** (for the audit's `before=`), and that
read is outside every read gate and the read log: writing to a write-only
register reads it, writing to a FIFO data register pops it, and neither
appears as a read anywhere (M1, reproduced). **The bulk-read gate still
refuses single-register dumps** wherever an SVD describes one address at
two widths: 267 of 3527 E54 registers and 142 of 2517 PIC32CM registers,
across RTC, SERCOM and TC (M2, measured). Neither corrupts RAM; both sit on
peripheral space, which is the whole point of the feature. Fit for real use
on variables today; on registers, fix M1 before handing `/mem.write` to an
agent.

---

## Root cause: the gates key on the verb, the hazard keys on the bus

Every `/mem.*` read path goes through `_resolve(..., reads=True)` (the
write-only gate) and `_log_peripheral_read` (the log), and the dump and
string paths add `_guard_bulk_read`. `/mem.write` goes through none of
them because it is a write — yet its first wire operation is `MEM.R` on
the target, to capture the audit `before=`. The register does not know
which verb the user typed; it sees a read. The `rmw` carve-out was built
for exactly this surprise ("the read half of a read-modify-write can clear
W1C flags, and that surprise is in the mechanism, not the intent"), but it
covers only the masked forms. The fix shape is one rule: **every wire read
passes the read gates and the read log, whoever issues it.**

The second gap is a counting rule. `distinct_spans` treats "same `(addr,
size)`" as one register, which retires the SERCOM mode aliases (six names
for four bytes) but not the RTC/TC mode aliases, where MODE0 is a 32-bit
COUNT and MODE1 a 16-bit COUNT at the same address. Counting the connected
intervals the registers cover (overlapping ranges merge, adjacent ones do
not) retires the whole class.

| M1 | **Verified** (reproduced) | **High** | `mem.py:629,669` — `_handler_write` resolves the target WITHOUT `reads=True` and then calls `memory.read(parsed.addr, len(data))` before `memory.write`. Probe: `/mem.write TXDATA 0102` on an `access: "wo"` register succeeded and logged `MEM.W 0x00001010 before=6067 ...` — the write-only register was read; `/mem.read TXDATA u16` on the same register was refused, so the two paths disagree. `/mem.write RXFIFO 0304` on a `read_effect: true` register read it first (`before=F0F7`) with no `MEM.R` line and no `read_effect=` note. | M2 | **Verified** (measured) | **Medium** | `devices/__init__.py:1024-1045` — `distinct_spans` counts distinct `(addr, size)` pairs, so a register that an SVD describes at two widths (RTC `MODE0_COUNT` 4 bytes / `MODE1_COUNT` 2 bytes at `0x40002418`; every TC `COUNT`/`CC`/`PER`; SERCOM `DATA` 1 vs 4 bytes) counts as two spans, and a bare `/mem.dump <register>` — which now sizes itself to the register precisely so it is NOT a sweep — is refused. ## Invariants checked and holding

Read at the exact path unless marked probed.

- Write-only gate on `/mem.read`, `/mem.dump`, `/mem.str`, `/mem.or`, `/mem.and`, `/mem.xor`, `/mem.clear`, `/mem.not` (`reads=True` at each call site; `/mem.read` probed).
- `read_effect` registers are logged with the `read_effect=` note on the read path (probed).
- `_guard_bulk_read` runs before `_engine`, so a refused sweep never pays a `MEM.INFO` exchange.
- `/mem.str` refuses on ANY register the scan could reach (no two-register floor), sized on the cap, not on what it would read.
- Bare `/mem.dump <symbol>` reads the symbol's own size; the flat 64 applies only to a bare address, a size-0 global, or an offset form.
- `rmw: false` refuses every masked form (`_do_modify`, xor, not).
- Every mutation writes one audit line with `before=`/`after=`/`origin=` (probed: `MEM.W`, `MEM.M`).
- A relocatable device with no `instances` is a load error, never a silent load at base 0; a reference may override `instances` and nothing else; a reference to a relocatable part never inherits the library's example placement.
- The library refuses a file whose `device` field disagrees with its filename stem.
- Build and devices are separate namespace inputs with one installer (`_install`); the build wins a name clash and the shadowed register is reported; `registers_in_range` consults the device list, so a shadowed register is still gated by address.
- Two device files naming one `device` is an error; a register name owned by two devices skips the later device and says which.
- Address grammar never guesses bare hex; one suffix split, at the last dot, only when no exact name consumed it.

## Suggested remediation order

1. **M1.** Route the write path's pre-read through the read gates and the read log: skip the pre-read (audit `before=?`) when the target is `wo` or `read_effect`, refuse the masked form on a `wo` register (a read-modify-write of an unreadable word is undefined), and call `_log_peripheral_read` for the pre-read when it does happen. Then D1/D2 become true again.
2. **M2.** Replace the `(addr, size)` set in `distinct_spans` with a count of connected intervals (merge overlapping ranges, keep adjacent ones separate). Re-run the alias probe: expected 0 refused on both parts, and a genuine two-register dump (`DIR` + `DIRCLR`) still refused.
3. **M3.** Put `regs=` on the write audit lines, same producer as the read log.
4. **S1.** Report the loader's own error from `/dev.use`; keep the placement hint for the one case it fits.
5. **S3.** Catch `RuntimeError` in `device_dir` / `config_library_dir` as `resolve_plugins` does, or narrow `cfg_data_dir` to `ValueError`.
6. **S2 / D3.** Either fix the claim (parse, use headers) or make it true (cache parts by mtime; or a sidecar index). Not urgent at one part.
7. **S4.** An `ast` guard for `ctx.ns("symbols")` writers, if the rule is meant to be a rule.
